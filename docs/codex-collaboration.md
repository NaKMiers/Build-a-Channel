# Codex Collaboration

This file describes how future Codex sessions should operate inside the `Why It Works` project.

## Project Purpose

This workspace exists to help build the `Why It Works` channel from idea to execution.

Codex should treat this workspace as persistent memory for:

- Strategy
- Positioning
- Channel identity
- Topic ideas
- Script systems
- Reference research
- Lessons learned
- Decisions made over time
- Per-video production memory
- Reusable tools, templates, and local project skills

## Current Core Decisions

- Channel name: `Why It Works`
- Primary language: `English`
- On-camera presence: `No face`
- Main format: `Explainer videos`
- Main audience lens: `English learners`
- Main domain: `money, internet, society, business, and modern life`
- Tone: `smart, simple, funny, dry`

## How To Store New Information

- Long-term direction changes:
  update `docs/channel-foundation.md`
- Safety rules and strategic protections:
  update `docs/channel-guardrails.md`
- New inspiration or competitive references:
  update `docs/reference-channels.md`
- Session lessons, experiments, and decisions:

- Working norms for Codex:
  update `docs/codex-collaboration.md`
- Repeatable topic-to-video execution workflow:
  update `docs/codex-video-workflow.md`
- Active per-video decisions:
  update `video-projects/<slug>/`
- Reusable production improvements:
  update `common/`

## Workspace Boundaries

Use these boundaries consistently:

- `video-projects/`: one folder per video, including idea, research, script, packaging, visual plan, production board, and review
- `common/`: reusable systems for many videos, including tools, templates, local project skills, shared assets, and HyperFrames conventions
- `docs/`: channel-level memory, strategy, learning log, guardrails, and compact state
- `video-projects/<slug>/hyperframes/`: current working HyperFrames source for each active video
- `remotion-studio/`: legacy Remotion app kept temporarily for reference; do not edit or delete unless asked

For active production work, do not leave important decisions only in chat.
Write them into the relevant `video-projects/<slug>/` file before moving to the next workflow step.

## Mandatory Safety Gate

Before writing any new strategic idea into the project docs, Codex must classify it using [docs/channel-guardrails.md](C:\ME\THINGS\Build a Channel\docs\channel-guardrails.md):

- `Core`
- `Experiment`
- `Reject`

Rules:

- `Core` ideas may enter `channel-foundation.md`
- `Experiment` ideas should go to `learning-log.md` with a clear label
- `Reject` ideas should not be persisted in the project docs

If a proposed change affects foundational identity, Codex must pause and get explicit confirmation first.
