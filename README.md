# TossExplains

Production repo for **TossExplains**, a YouTube channel of hand-drawn doodle explainers about
psychology, anthropology, and self-help.

Every video answers one question the viewer has personally felt ("why do you feel lonelier in a
crowd than alone in your room?") by hitting three pillars in order:

1. **Psychology**, the real mechanism in the mind, with named research
2. **Anthropology**, the ancestral world that installed it
3. **Self-help**, one concrete shift the viewer can make tonight

This repo holds no video editor and no rendering code. It holds the **agent pipeline** that
produces each episode's script, cast, prompts, and packaging, the **tools** that turn narration
audio into timestamps, and the **per-video artifacts** each episode produces.

The pipeline is nine skills, shared by **Codex** and **Claude Code** from one source of truth
under `.agents/`. If you are an agent, start at [AGENTS.md](AGENTS.md).

---

## The pipeline

Nine project-local skills. Each one validates its inputs, writes exactly one artifact, and names
the next command to run. Nothing is generated ahead of its inputs.

| Skill | Needs | Writes |
| --- | --- | --- |
| `/topic` | nothing | 5 titles in chat, then scaffolds `projects/<n>-<slug>/` |
| `/script` | a chosen title | `script_<short_slug>.md` |
| `/transcript` | script + recorded voiceover | `transcribes/transcript.md`, `transcribes/words.json` |
| `/cast` | script | `prompts/character-prompts.md` |
| `/scenes` | transcript + cast | `prompts/image-prompts.md` |
| `/metadata` | script | `metadata.md` |
| `/thumbnail` | script + cast | `prompts/thumbnail-prompts.md` |
| `/check` | anything | a PASS / FAIL / INFO report, read-only |
| `/skill-sync` | nothing | regenerates the Claude wrappers. Manual only |

After `/script` the branches run in parallel:

```
/topic -> /script -+-> /transcript -+-> /scenes
                   |                |
                   +-> /cast -------+-> /thumbnail
                   |
                   +-> /metadata

/check runs at any point
```

`/transcript`, `/cast`, and `/metadata` depend only on the script. `/scenes` needs the transcript
plus the cast. `/thumbnail` needs the script plus the cast, not the transcript.

The three image stages (`characters/`, `scenes/`, `outputs/`) are generated by you in an external
image tool from the prompt files this repo writes. The repo never calls an image model.

## Source of truth

`.agents/` is canonical. Both Codex and Claude read from it.

- `AGENTS.md` is Codex's auto-loaded entry point. `CLAUDE.md` is exactly `@AGENTS.md`, a Claude
  import, so the two can never drift.
- `.agents/rules/` is the channel brain, six files, read directly by both tools.
- `.agents/skills/<name>/` holds the real skill: `SKILL.md`, `references/memory.md` (its
  self-improving notes, one canonical copy), and `agents/openai.yaml` (Codex discovery).
- `.claude/skills/<name>/SKILL.md` is a thin generated wrapper that carries only the frontmatter
  Claude needs to discover the skill, then delegates back. Wrappers instead of symlinks because
  the project is committed to git and may travel to Windows.

Edit skill logic and memory only under `.agents/skills/`, then run `/skill-sync`. See
[.agents/README.md](.agents/README.md) and [.claude/README.md](.claude/README.md).

### Why rules are single-sourced

The four verbatim prompt strings (STYLE ANCHOR, STYLE LOCK, GENERATION LINE, REFERENCE SHEET
OPENING LINE) once appeared 7, 7, 7, and 2 times across the old prompt files. A thumbnail rule
was fixed in one copy while two others still contradicted it, and the contradiction survived
undetected. They now live once, in
[.agents/rules/visual-style.md](.agents/rules/visual-style.md).

Nothing greps for them by hard-coded pattern either. Skills `source .agents/bin/style-strings.sh`,
which extracts the strings from the rule file at run time, so a verification pattern cannot drift
from the definition it is meant to be checking.

Only three other places may legally hold a copy: the two copy-pasteable layout templates in
`thumbnail-rules.md`, the grep helpers in the `scenes` and `check` skills, and the generated
artifacts under `projects/`. A copy anywhere else is a bug. This README deliberately does not
quote them.

## Making a new video

```bash
/topic          # pick a number from the 5 titles; scaffolds projects/<n>-<slug>/
/script         # writes script_<short_slug>.md
```

Record the narration from that script, drop the audio into `audios/`, then:

```bash
/transcript     # audios/*.mp3 -> transcribes/transcript.md
/cast           # -> prompts/character-prompts.md
```

Generate one image per code block in `character-prompts.md`, attaching `brand/MASCOT.jpeg` for the
`YOU` sheet, and save each as `characters/NAME.jpeg`. Then:

```bash
/scenes         # one prompt per timestamp -> prompts/image-prompts.md
/metadata       # -> metadata.md
/thumbnail      # 5 A/B concepts -> prompts/thumbnail-prompts.md
```

Generate each scene image with only the sheets for the `@` tokens in that prompt attached, plus the
generation line from the file header, and save it to `scenes/` named by its timestamp. Generate the
five thumbnails into `outputs/`, rename the winner with an `-accepted` suffix, then:

```bash
/check          # validates everything against the rule files
```

Assemble and upload.

**Tip from the `scenes` skill:** generate the 3 or 4 frames where your main character is most
visible first. If any drifts from the reference sheet, fix it before generating the other 250.
Drift compounds.

## Why the cast exists

The channel's one hard visual failure mode is **character drift**: the same person looking slightly
different in every frame, so the video reads as if five people drew it.

The fix is a named cast, locked before any scene image exists. Each member gets a ONE-WORD ALL-CAPS
name and a reference sheet saved as `characters/NAME.jpeg`. From `/scenes` onward, a prompt refers
to a character **only** as `@NAME` and never re-describes them. The sheet carries the design, the
prompt carries only action, expression, posture, and framing. No `@` token may be used unless it
exists in that video's cast table, and `/check` enforces that.

Three things a human needs to know, all specified in
[mascot-toss.md](.agents/rules/mascot-toss.md):

- **`@YOU` is always Toss**, the channel mascot and the viewer stand-in in every video. His design
  is fixed channel-wide and is never re-derived from the script. His signature is **exactly two
  hair peaks**, drawn as one closed shape merging into the head outline: not three spikes, not
  four, not a fringe. Only his costume changes per video, and costume color is free, because
  recognition comes from the head, hair, face, and build, never from a color.
- **The `YOU` sheet is an image edit of `brand/MASCOT.jpeg`, not a description.** Describing Toss
  from scratch and hoping the model rebuilds him identically is exactly how the two-peak tuft turns
  into four spikes between videos. If the description and the attached image ever disagree, the
  image wins.
- **Every other cast member is derived from the script, never templated.** There is no house cast
  and no default ancestor. If the anthropology section is set in a monastery, the character is a
  monk, not a caveman. Two scripts should almost never produce the same cast. Cast size is 2 to 6,
  fewer is better, and a recurring group counts as one entry.

The character build is a **hybrid**, and both halves of that matter: a big circle head at one third
of total height, thin single-line limbs, and ONE filled garment standing in for the torso. It is
explicitly not a pure line stickman with a single-line spine, and not a fully drawn cartoon person.
Hands are small splayed line fingers, three or four short strokes off the arm line, never mittens.

## What a frame looks like

Flat colors, bold black outlines, sketchy marker lines, always 16:9. Flat solid color backgrounds
only: zero gradients, zero shadows, zero textures. Emotion lives in the eyebrows, the mouth line,
the posture, and the head color, never in background detail. Keep every frame down to the fewest
objects that carry the idea, and translate abstractions into concrete objects rather than drawing
the abstraction.

The two numbers that get a set rejected when they slip, both budgeted in
[visual-style.md](.agents/rules/visual-style.md):

- **Plain white is the default and must be the clear majority, 55 to 75 percent of prompts.** The
  accepted fixture runs 58 percent white. Project 2's rejected first pass ran 37 percent.
- **Cobalt blue is capped at 15 percent and means literally inside the mind**, a brain or a thought
  loop as the subject. It does not mean night, sad, or serious. A 2am bedroom is modern everyday
  life and gets white. So do labs.

On-screen text is bold ALL CAPS hand-lettered marker at the top of the frame: black by default, red
for danger, threat, failure, or negation, and never yellow on white because it is unreadable.

Every scene prompt is exactly one unbroken line that opens with its timestamp copied character for
character from the transcript, opens with the STYLE ANCHOR, and closes with the STYLE LOCK. The
timestamp and the `@` tokens are instructions for you and the file system, never visual content,
which is why the style lock repeats that negative. Scene filenames derive from the timestamps by
replacing `:` with `-`, so `[3:20]` is saved as `[3-20].jpg` and works on Windows.

## Thumbnails

The thumbnail decides whether the video is watched at all, so it is generated to a fixed proven
pattern rather than invented per video. The pattern comes from a teardown of two channels in the
niche plus our own A/B round, in
[research/thumbnail-swipe/ANALYSIS.md](research/thumbnail-swipe/ANALYSIS.md) with the 40 sampled
thumbnails beside it. The rules are in
[thumbnail-rules.md](.agents/rules/thumbnail-rules.md); the load-bearing ones:

- **Every noun in the question must be a physical object drawn in the frame.** `FIRST SALT?` works
  because salt is on the ground. `WHY THE HOLLOW?` failed because nothing in the frame answers
  "about what?". This one rule killed both our first rounds.
- Always a question, 2 to 4 words, ALL CAPS, and it must never restate the title.
- The text runs perfectly straight across the very top, full bleed, yellow on the darkest band in
  the image. Never arced.
- Never a lone figure on an empty background, and never a flat single-color background: it renders
  as a dead frame with large void areas.
- Co-stars need visible faces with visible expressions. Asking for featureless or blank heads
  produced a field of giant white eggs that ate the frame.

Five concepts per video, each built on a different moment from the script, at least two using the
split comparison layout. Shrink your favourite to 120 px wide: if the question is not readable and
the emotion is not obvious in half a second, regenerate rather than adding text. The logo badge is
added in the editor, bottom-left, because the image model garbles it.

## Tools

Both scripts emit the `[M:SS] line of narration` format that `/scenes` consumes, and both share
[tools/tsfmt.py](tools/tsfmt.py). `tsfmt` breaks lines where the narrator actually paused and after
every sentence, so a short sentence keeps its own line, then folds stray fragments back into a
neighbour so a dramatic pause never leaves a one-word line with nothing to draw. It also knows that
a lone capital plus a period is a personal initial ("E. J. Masicampo"), not the end of a sentence.

### `audio-to-timestamps.py`, narration audio to transcript

```bash
# Forced alignment (default when --script is given, needs ELEVENLABS_API_KEY).
# You supply the audio AND the script it was read from, so the words are yours and
# only the timing comes from the API. Roughly $0.08 for a 12 minute video.
python3 tools/audio-to-timestamps.py projects/4-.../audios/part-1.mp3 \
    --script projects/4-.../script_why_your_life_feels_faster.md \
    --save-json projects/4-.../transcribes/words.json \
    -o projects/4-.../transcribes/transcript.md

# Plain transcription, no script needed (needs GROQ_API_KEY, whisper-large-v3-turbo,
# under a cent per video). Wording and punctuation can drift from what you wrote.
python3 tools/audio-to-timestamps.py voice.mp3 --engine groq -o transcript.md

# Several files are treated as consecutive parts of one recording, so part 2 continues
# where part 1 ended. With alignment, pass one --script per audio file, in the same order.
python3 tools/audio-to-timestamps.py part-1.mp3 part-2.mp3 --script s1.md --script s2.md
```

Always pass `--save-json`. It caches the word timings so the transcript can be re-cut at a
different granularity for free:

```bash
python3 tools/audio-to-timestamps.py --from-json .../words.json --max-dur 5 -o transcript-min5.md
```

Cutting flags: `--pause` (new line wherever the narrator paused this long, default 0.30),
`--max-dur` (split any line holding more than this much video at its widest internal pause,
default 4.5, 0 disables), `--min-words` (fold shorter fragments into a neighbour, default 3),
`--max-chars` (off by default), `--min-dur` (glue lines back together *after* splitting, only to
cut how many images you pay for), `--no-split-sentences`, `--pad` for `[00:05]` instead of `[0:05]`,
and `--timeout` (default 900s).

A 12 minute script lands around 230 to 270 lines of roughly 3 seconds each with the defaults. Under
20 lines means the transcript is incomplete, and both `/transcript` and `/check` fail it.

### `srt-to-timestamps.py`, existing subtitles to transcript

```bash
python3 tools/srt-to-timestamps.py part-1.srt part-2.srt -o transcript.md
python3 tools/srt-to-timestamps.py caption.vtt --min-dur 5 --max-chars 180
python3 tools/srt-to-timestamps.py part-2.srt --offset 4:12
```

Reads SRT or VTT, strips tags and cue settings, and collapses YouTube's rolling-caption repeats
unless you pass `--keep-repeats`. Files are consecutive parts by default; `--offset` (repeatable,
`M:SS` or plain seconds) overrides the start time of a given file. No API call and no cost.

### API keys

Put them in a gitignored `.env` at the repo root, or export them. `audio-to-timestamps.py` looks
for a `.env` in the working directory first, then beside the tool and up the repo tree, and it
never overrides a value already set in your shell.

```
ELEVENLABS_API_KEY=...    # also accepts ELEVENLAB_API_KEY, ELEVEN_API_KEY, XI_API_KEY
GROQ_API_KEY=...
```

Groq's free tier caps uploads at 25 MB per file; over that, split the recording or use alignment.

## Conventions that bite

Every one of these was learned from a failure, and `/check` looks for most of them.

- **No em dash anywhere.** Not in scripts, titles, descriptions, tags, prompts, rule files, or chat
  replies. ASCII only otherwise, with one sanctioned exception: the middle dot used as a separator
  in the cast line of a prompt file header.
- **No markdown inside `script_<short_slug>.md`**, despite the `.md` extension. The forced aligner
  flattens the whole file into one word stream, so a stray `##` or `**` becomes a spoken token and
  corrupts every timestamp after it. This is a hard FAIL, not a style nit.
- **All prose files are `.md`.** `words.json` is the only exception, because it is data.
- **One prompt is exactly one unbroken line**, separated from the next by exactly one blank line.
  Downstream tools split these files on newlines, so a wrapped prompt is two broken prompts.
- **Timestamps are file names.** Copy them character for character. If the transcript repeats a
  timestamp, the `image-prompts.md` header must declare the remap, for example "`[3:24]` appears
  twice; save the second one as `[3:25]`". Project 1 has exactly this case.
- **`outputs/` and `audios/` are plural.** Character sheets are `.jpeg`, not `.png`.
- **`prompts/video-prompts.md` is empty on purpose.** It is a reserved slot and never a defect.
- **Never ask the user to describe the channel.** The style, palette, voice, pillars, and mascot are
  all in `.agents/rules/`. Read the rule file.

## Editorial guardrails

Non-negotiable, from [channel-dna.md](.agents/rules/channel-dna.md):

- **Never shame the viewer.** The emotional promise is relief: you are not broken, you are running
  ancient software in a world it was never written for.
- **Never diagnose, never prescribe treatment, never mention medication.** If a topic brushes
  anxiety, depression, or trauma, stay at the level of ordinary human experience.
- Second person throughout, "you" and "your brain" and "your ancestors". Never "we" or "I".
- Every scientific term decoded in plain English immediately, and at least 3 real named researchers
  per script, at least one of them an anthropologist or ethnographer. Never invent a study.
- History and prehistory are supporting material, never the subject. If a script could run without
  the viewer's inner life in it, it is the wrong script.
- The takeaway is ONE understood shift, delivered as a reframe, never a numbered checklist.
- End on a closing line that echoes the opening, completely reframed.
- **Off-limits:** pure history with no inner-life payoff, pure advice with no science underneath,
  dated news, politics, religion as a truth claim, medical prescriptions.
```
