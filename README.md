## Video Lifecycle

The channel uses a `0-9` production flow with packaging as a side branch:

0. Topic intake
1. Research pack
2. Script draft
3. Packaging: title, thumbnail, and YouTube description
4. Voiceover
5. Visual plan
6. Render
7. Review
8. Upload
9. Learning

Main production chain:

```text
TopicIntake -> ResearchPack -> ScriptDraft -> Voiceover -> VisualPlan -> Render -> Review -> Upload -> Learning
```

Packaging side branch:

```text
ResearchPack -> Packaging
```

Future skills should follow this graph and write their outputs into the relevant `projects/<slug>/` folder.

After voiceover, production may branch by section: each selected section gets its own visual plan, render preview, and review path.

Render port rule:

- unified/final preview uses `localhost:1000`
- section `N` preview uses `localhost:1000 + N`
- Section 1 uses `localhost:1001`, Section 2 uses `localhost:1002`, and so on

Pipeline rule:

- each step requires the previous step outputs before it runs
- if a required previous output is missing, run the missing skill first
- if an earlier step is rerun, every later step output becomes stale and should be removed by explicit request or regenerated by rerunning later skills in order
- packaging is outside the main pipeline; it requires only `00-topic-intake.md` and `01-research-pack.md`
- packaging does not block script, voiceover, visual plan, render, review, upload, or learning

## Core Rule

If something belongs to one video, put it in `projects/<slug>/`.

If something should improve many videos, put it in `.agents/_shared/`.

If it is an executable Codex skill, put it in `.agents/skills/`.

If it is a rule for how Codex or future skills should behave, put it in `.agents/rules/`.

Before writing any core strategy change, use [channel-guardrails.md](C:\ME\THINGS\Build a Channel\.agents\_shared\channel\channel-guardrails.md) and classify the change as `Core`, `Experiment`, or `Reject`.
