This workspace exists to help build the `Why It Works` channel from idea to execution.

Codex should treat this workspace as persistent memory for:

- Strategy
- Positioning
- Channel identity
- Topic ideas
- Script systems
- Reference research
- Lessons learned
- Decisions made over time
- Per-video production memory

## Workspace Boundaries

Use these boundaries consistently:

- `projects/`: one folder per video, including idea, research, script, packaging, visual plan, production board, and review
- `.agents/_shared/`: reusable systems for many videos, including tools, templates, local project workflows, shared assets, and HyperFrames conventions
- `.agents/_shared/channel/`: channel-level memory, strategy, learning log, guardrails, and compact state
- `projects/<slug>/hyperframes/`: current working HyperFrames source for each active video
- `.agents/_shared/remotion/`: legacy Remotion notes kept for reference; do not revive legacy Remotion production unless asked

For active production work, do not leave important decisions only in chat.
Write them into the relevant `projects/<slug>/` file before moving to the next workflow step.

## Mandatory Safety Gate

Before writing any new strategic idea into the project docs, Codex must classify it using [.agents/_shared/channel/channel-guardrails.md](C:\ME\THINGS\Build a Channel\.agents\_shared\channel\channel-guardrails.md):

- `Core`
- `Experiment`
- `Reject`

Rules:

- `Core` ideas may enter `channel-foundation.md`
- `Experiment` ideas should go to `learning-log.md` with a clear label
- `Reject` ideas should not be persisted in the project docs

If a proposed change affects foundational identity, Codex must pause and get explicit confirmation first.
