# Thumbnail Visual Rules

Classification: `Core`

Scope: `CHANNEL_WIDE`

Purpose:
define the visual rules for future `Why It Works` thumbnails.

These rules do not create thumbnails for any existing video project.

## Core Visual Promise

The thumbnail should look like a normal object has started behaving suspiciously.

It should feel:

- simple
- funny
- slightly weird
- emotionally obvious
- readable for English learners
- distinct from clean educational slides

Working rule:

`Do not make the thumbnail a diagram. Make it a tiny problem.`

## Canvas

Use standard YouTube thumbnail size:

```text
1280 x 720
16:9
```

Safe layout:

- keep key text inside the central `80%`
- keep WIT's face and the dominant object away from the outer `60px`
- avoid important details in the bottom-right corner where UI overlays may appear
- test at small size before approval

## Visual Hierarchy

Every thumbnail should have this order:

1. Dominant object
2. Visual contradiction
3. WIT emotion
4. Short label
5. Small supporting details

If the viewer sees the label first and only then understands the image, the concept is too text-dependent.

## Dominant Object Rules

Use one object as the anchor.

Good objects:

- phone
- wallet
- receipt
- shopping cart
- calendar
- checklist
- price tag
- product box
- laptop
- app screen
- bill
- tiny store counter

The object should be real-looking or physically specific.
Avoid clean generic icons unless the object itself is not the joke.

## Contradiction Rules

The contradiction must be visible.

Useful contradiction types:

- free object with a hidden checkout
- cheap object with a visible downgrade
- simple button with a trap behind it
- useful checklist that cages WIT
- small bill leaking many tiny costs
- friendly interface acting like a machine
- normal receipt becoming too long
- discount tag hiding a worse product

Avoid:

- generic locks
- generic warning triangles
- generic money bags
- generic charts
- abstract symbols with no physical joke

## WIT Rules

Thumbnail WIT should not be calm.

Use one clear emotion:

- suspicious
- betrayed
- trapped
- panicked
- confused
- defeated

WIT should:

- face or react toward the object
- be large enough that glasses, eyes, and mouth read at mobile size
- have simple silhouette and clean edge separation
- support the question, not explain the topic like a presenter

Do not use neutral WIT in thumbnails.

## Text Rules

Use `1-3` words max.

Text should be:

- large
- high contrast
- handwritten-looking when possible
- close to the object it labels
- different from the title

Good text formats:

```text
[WORD]?
[WORD]*
NOT [WORD]
WHY?
BROKEN?
```

Avoid:

- full sentences
- subtitles
- more than one main label
- small labels that only work on desktop
- decorative text that does not create tension

## Color Rules

Use strong contrast without turning every thumbnail into one color family.

Recommended structure:

- simple background color or two-tone flat background
- one high-contrast object color
- one warning or emphasis color
- WIT separated with outline, shadow, or background gap

Avoid:

- muddy low-contrast palettes
- mostly beige, mostly purple-blue, mostly dark slate, or mostly brown/orange palettes
- detailed backgrounds
- gradient-orb decoration
- color choices that make WIT blend into the object

## Layout Patterns

Prefer these reusable compositions:

### Object Left, WIT Right

Use when the object is the villain and WIT reacts to it.

Best for:

- hidden cost
- suspicious app
- dangerous receipt
- confusing price

### Object Center, WIT Corner

Use when the object itself is strange enough to dominate.

Best for:

- product downgrade
- fake bargain
- weird machine
- overgrown receipt

### Trap Around WIT

Use when the system physically captures or pressures WIT.

Best for:

- subscriptions
- productivity loops
- app retention
- monthly payments

### Before/After Lie

Use when the topic is about a promise versus reality.

Best for:

- cheap products
- productivity advice
- convenience
- online claims

## Mobile Test

Before approval, shrink the mockup to around `10%` size or view it as a small grid thumbnail.

It passes only if:

- the object is identifiable
- WIT emotion is still readable
- the label is readable
- the contradiction still creates a question
- the thumbnail is not just text and color

## Reference Comparison

When checking against reference thumbnails, compare principles, not exact style.

Look for:

- one strong visual question
- simple read
- emotional face or character reaction
- title-thumbnail tension
- no wasted detail

Do not copy another creator's composition exactly.

## Export Notes

Future reusable mockups should use:

```text
1280x720
PNG or JPG
high contrast
clean edges
no baked-in copyrighted brand logos
```

Keep source files in the relevant future video project only after the user explicitly asks to apply packaging to that video.
