# Why It Works Script Tone System

Classification: `Core`

Scope: `CHANNEL_WIDE`

Purpose:
make every future `Why It Works` script feel like a deadpan creator exposing a weird modern system in simple English, not like a polite school essay.

This system applies to new scripts and rewrites from this point forward. It does not rewrite any existing video project by itself.

## Core Voice

The channel voice is:

- clear
- simple
- dry
- skeptical
- observant
- lightly tired of modern life
- funny without announcing the joke

The channel voice is not:

- academic
- corporate
- motivational
- slang-heavy
- fake-deep
- too polished
- native-speaker-only comedy

Default narrator feeling:

`A calm 23-year-old explains a weird system because apparently everyone decided this is normal.`

## Main Script Rule

Every major section must answer two questions:

1. What is the explanation?
2. What is the funny image?

If a section only explains, it is not finished.

If a joke cannot become a clear visual, it is probably not the right joke for this channel.

## Channel Premise

The video should not feel like:

`Today I will teach you a topic.`

It should feel like:

`Here is a normal thing you already live with. It is actually ridiculous. Let us look at why.`

The viewer should feel:

- `That is true.`
- `I never noticed it that way.`
- `This is stupid, but it makes sense.`
- `I understood the topic and the English.`

## Default Script Shape

Use this structure for most long-form scripts:

1. `Hook`: expose the contradiction within 10 seconds.
2. `Reframe`: say what the video is really about.
3. `System setup`: show the main metaphor.
4. `Section 1`: explain one cause and one funny image.
5. `Section 2`: explain the next cause and raise the pressure.
6. `Section 3`: show why the system keeps working.
7. `Payoff`: land the bigger insight.
8. `Outro`: exit quickly.

## Required Script Ingredients

Each long video should include:

- one main metaphor
- one repeated phrase
- one running visual joke
- one fake-serious line
- one absurd comparison
- one painfully relatable example
- one final insight that feels bigger than the topic

These ingredients should support the explanation. They should not turn the video into random comedy.

## Deadpan Transformation Pattern

Start with a plain explanation, then turn it into a concrete deadpan observation.

Weak:

```text
Free is not always the absence of payment. Sometimes it is just the removal of friction.
```

Better:

```text
Free does not mean no one is paying. It usually means the cashier is hiding behind a plant.
```

Weak:

```text
Apps use retention to increase ad inventory.
```

Better:

```text
Every extra minute you spend scrolling becomes a tiny product sitting on a shelf called attention inventory.
```

Pattern:

```text
Formal idea:
_____

Concrete system:
Who is doing what to whom?
_____

Deadpan image:
What would this look like if it became a tiny physical scene?
_____

Final line:
_____
```

## Tone Levers

Use these to make lines feel more like `Why It Works`.

### 1. Suspicious Normality

Treat normal modern things as quietly strange.

```text
Somehow we all agreed that the best way to buy socks is to create an account.
```

### 2. Fake Seriousness

Use official-sounding language for silly human behavior.

```text
This is known in economics as `standing in the kitchen, checking your bank app, and becoming religious for eight seconds`.
```

### 3. Literal Systems

Turn invisible systems into physical objects.

```text
The algorithm is basically a tiny manager with a clipboard asking, `Can this person waste two more minutes?`
```

### 4. Painfully Relatable Examples

Use everyday situations the audience already understands.

```text
You open the app to check one thing. The app says, `Good. Now live here.`
```

### 5. Dry Correction

Say the obvious correction after the joke.

```text
This is not a business model. This is a vending machine that learned psychology.
```

## Section Standard

Each section needs:

- one clear point
- one funny visual
- one phrase worth putting on screen
- one reason for WIT to exist
- one sentence that moves the story forward

Good section flow:

```text
Point: what is happening?
Tension: why is it weird or unfair?
Image: what does this look like on screen?
Explanation: why does it work?
Memory phrase: what should the viewer remember?
Bridge: why does the next section happen?
```

## WIT In Scripts

WIT should appear when the system needs a human target.

Best uses:

- WIT gets charged by something invisible.
- WIT follows a simple instruction and loses control.
- WIT thinks he found a shortcut, then the system appears.
- WIT reacts to a label that explains the real cost.
- WIT silently proves the joke by suffering.

Weak uses:

- WIT stands beside text for no reason.
- WIT explains the topic like a teacher.
- WIT repeats what the narrator already said.
- WIT appears only because a scene needs decoration.

Rule:

`If WIT is on screen, the system should be happening to him or through him.`

## On-Screen Text Standard

On-screen text should be short, visual, and useful for English learners.

Use it for:

- repeated phrases
- key nouns
- joke labels
- simple diagrams
- fake-serious labels
- corrections and cross-outs

Good labels:

```text
FREE*
attention inventory
tiny monthly leak
normal adult problem
definitely not a trap
```

Avoid:

- full paragraphs on screen
- abstract labels with no image
- captions that fight the voiceover
- fancy words when common words work

## Learner-Friendly Tone Rules

The channel is English-first, but learner-friendly by design.

Use the full channel-wide clarity system in [english-learner-clarity-system.md](english-learner-clarity-system.md), [english-learner-script-checklist.md](english-learner-script-checklist.md), [english-learner-useful-phrase-rules.md](english-learner-useful-phrase-rules.md), and [english-learner-humor-clarity-rules.md](english-learner-humor-clarity-rules.md) before approving future scripts.

Keep:

- short sentences
- common words
- repeated keywords
- clear signposting
- examples from daily life
- jokes that work from context

Avoid:

- dense idioms
- fast cultural references
- long abstract paragraphs
- jokes that hide the main meaning
- sarcasm that only native speakers understand

Rule:

`The viewer should understand the point even if they miss one joke.`

## Script Pass Workflow

Use this order for every future script:

1. Write the plain explanation.
2. Identify the main contradiction.
3. Choose the recurring metaphor.
4. Add one visual joke per section.
5. Replace formal lines with concrete deadpan lines.
6. Remove lines that the visual already explains.
7. Add repeated phrases for memory.
8. Check learner clarity.
9. Read aloud with real pauses.
10. Cut anything that sounds like a school essay.

## Pass Or Fail

A script pass is successful if:

- the hook creates tension within 10 seconds
- each section has a visual joke
- the repeated metaphor appears at least 3 times
- WIT has a clear reason to exist when used
- the ending lands a real insight
- the script is readable for intermediate English learners
- no section feels like generic educational content

If it fails, do not polish the wording yet.
Fix the section idea, image, or metaphor first.
