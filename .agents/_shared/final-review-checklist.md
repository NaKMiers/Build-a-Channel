# Final Review Checklist

Classification: `Core`

Scope: `CHANNEL_WIDE`

Purpose:
provide a reusable final review and upload gate for future `Why It Works` videos after a full rough cut exists.

Use this after pre-production has passed and a full cut is available. This checklist does not audit any existing video by itself.

## Pass/Fail Rule

The final cut must pass all critical areas:

```text
Package match
First 10 seconds
Retention
Visual board quality
WIT usage
Learner clarity
Audio clarity
Asset safety
Final upload readiness
```

Decision options:

```text
PASS: ready for upload or scheduled upload
FIX: revise listed issues, then review again
FAIL: not uploadable in current form
```

## 1. Package Match

```text
[ ] title and thumbnail still match the final video
[ ] thumbnail promise appears in the first `10` seconds
[ ] title names the hidden logic, not only the topic
[ ] thumbnail shows the weird situation, not a generic icon
[ ] WIT emotion in the thumbnail matches the opening feeling
[ ] title and thumbnail do not repeat the same words
```

Hard fail:
the package promises a more interesting video than the cut delivers.

Decision:

```text
Package match: PASS / FIX / FAIL
```

## 2. First `10` Seconds

```text
[ ] topic is clear without audio by second `3`
[ ] contradiction appears by second `5`
[ ] WIT emotional position is clear by second `8`
[ ] viewer has a reason to continue by second `10`
[ ] no branding, title-card delay, or polite setup slows the opening
[ ] first line sounds like a person, not a classroom intro
```

Watch the first `10` seconds:

```text
[ ] with audio
[ ] without audio
[ ] at mobile size
[ ] paused at seconds `1`, `3`, `6`, and `9`
```

Decision:

```text
First 10 seconds: PASS / FIX / FAIL
```

## 3. Retention Pass

```text
[ ] every `5-10` seconds has a reason to watch
[ ] every section has at least one visual idea
[ ] no long dead clean-board stretches
[ ] visual changes follow meaning, not random motion
[ ] repeated motif returns often enough to feel intentional
[ ] jokes have space to land
[ ] ending delivers a memorable insight
```

Reasons to watch can include:

- new evidence object
- WIT reaction
- red correction
- label reveal
- contradiction escalation
- clear example
- punchline
- section turn
- memorable phrase

Decision:

```text
Retention: PASS / FIX / FAIL
```

## 4. Paused-Frame Review

Sample frames from each section.

```text
[ ] paused frame is understandable
[ ] one thought per frame
[ ] labels are readable
[ ] WIT is not cropped awkwardly
[ ] main object is not blocked
[ ] red markup points to something specific
[ ] no screen feels like a blank slide
[ ] no screen is overloaded with equal elements
```

Hard fail:
many paused frames look clean but meaningless.

Decision:

```text
Paused-frame review: PASS / FIX / FAIL
```

## 5. WIT Review

```text
[ ] WIT has multiple memorable reactions
[ ] WIT is emotionally clear at small size
[ ] WIT reacts to the system, object, or contradiction
[ ] WIT is not used as a neutral presenter by default
[ ] WIT does not block important labels or objects
[ ] WIT appears often enough to create channel identity
[ ] WIT is absent when the board is stronger without him
```

Working rule:

```text
WIT is funniest when the system is happening to him.
```

Decision:

```text
WIT usage: PASS / FIX / FAIL
```

## 6. Real-Life Texture Review

```text
[ ] real-life assets or real-looking evidence appear where useful
[ ] objects support explanation, not decoration
[ ] receipts, phones, bills, mockups, desks, papers, or app-like screens feel connected to daily life
[ ] source notes exist where needed
[ ] private data is not visible
[ ] real logos or copied screens are avoided unless explicitly justified
```

Decision:

```text
Real-life texture: PASS / FIX / FAIL
```

## 7. Learner-Friendly Review

```text
[ ] narration is easy to follow for intermediate English learners
[ ] key phrases are visible or repeated naturally
[ ] captions and labels support the voice
[ ] dense ideas are broken into simple lines
[ ] jokes work from context
[ ] no fast abstract section loses the viewer
[ ] useful English appears naturally, not as a lesson interruption
```

Use [english-learner-clarity-system.md](english-learner-clarity-system.md), [english-learner-script-checklist.md](english-learner-script-checklist.md), [english-learner-visual-checklist.md](english-learner-visual-checklist.md), [english-learner-useful-phrase-rules.md](english-learner-useful-phrase-rules.md), and [english-learner-humor-clarity-rules.md](english-learner-humor-clarity-rules.md) when a learner-clarity issue is unclear or disputed.

Hard fail:
the explanation is correct but sounds like a fast native-speaker essay.

Decision:

```text
Learner clarity: PASS / FIX / FAIL
```

## 8. Audio Review

```text
[ ] narration is always the clearest layer
[ ] music supports dry humor without dominating
[ ] sound effects do not cover important words
[ ] dense explanation sections stay clear
[ ] punchlines have enough quiet space
[ ] playback works on laptop speakers
[ ] playback works on headphones or earbuds
[ ] low-volume playback remains understandable
```

Use [audio-mixing-checklist.md](audio-mixing-checklist.md) for the full audio gate.

Decision:

```text
Audio: PASS / FIX / FAIL
```

## 9. Visual Safety And Asset Review

```text
[ ] no copied reference material
[ ] no unsafe copyrighted assets
[ ] no unclear licensed music or effects
[ ] no real private data
[ ] no copied app screens with sensitive or brand-heavy content
[ ] generated, self-made, public-domain, licensed, or safe mockup assets are documented
[ ] source notes are stored with reusable assets or future per-video assets
```

Hard fail:
an asset is necessary to the video but its source or safety is unclear.

Decision:

```text
Asset safety: PASS / FIX / FAIL
```

## 10. Final Upload Checklist

Before upload:

```text
[ ] final title approved
[ ] final thumbnail approved
[ ] title and thumbnail match
[ ] first `10` seconds pays off thumbnail
[ ] WIT has multiple memorable reactions
[ ] real-life assets appear where useful
[ ] music supports, not dominates
[ ] video remains learner-friendly
[ ] captions or readable on-screen text are ready
[ ] no copied reference material
[ ] no unsafe copyrighted assets
[ ] export file plays from start to finish
[ ] upload metadata does not overclaim
```

Decision:

```text
Final upload checklist: PASS / FIX / FAIL
```

Decision:

```text
Post-upload review setup: PASS / FIX / FAIL
```

## Upload Standard

The final upload must feel like a strong `Why It Works` video, not merely a finished explainer.

It should be clear enough for English learners, funny enough to feel human, specific enough to earn the click, and safe enough to publish without relying on copied assets or misleading packaging.

After upload, use the publishing feedback loop to decide what should change in the next video.
